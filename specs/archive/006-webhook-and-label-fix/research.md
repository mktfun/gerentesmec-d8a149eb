# Research: Webhook Stability and Chatwoot Labeling

## 1. Problema de Interrupção das Mensagens
- **Ocorrência:** Há 12 minutos as mensagens pararam de chegar. Isso coincide exatamente com o deploy da nova edge function `chatwoot-webhook`.
- **Análise da Causa:** Durante a correção anterior, adicionamos as colunas `total_response_time_minutes` e `response_count` à tabela `leads` usando o comando SQL via terminal (`npx supabase db query`). O banco foi atualizado com sucesso. No entanto, a API RESTful do Supabase (PostgREST) utiliza um cache de schema para resolver as consultas. Como o cache não foi invalidado, quando o `chatwoot-webhook` tenta executar um `SELECT ... total_response_time_minutes`, o PostgREST lança um erro 400 (Bad Request - Column not found), resultando na quebra do webhook antes mesmo dele salvar a mensagem no banco.
- **Solução Parcial já Aplicada:** Eu enviei manualmente o comando `NOTIFY pgrst, 'reload schema'` no terminal. Isso *já reestabeleceu* as mensagens no momento em que você lê este documento. As mensagens já devem estar voltando a cair normalmente.

## 2. Problema na Atribuição da Etiqueta "Ignorar" (Delete Lead)
- **Ocorrência:** Quando o usuário exclui um card pelo CRM, a intenção era enviar a etiqueta `ignorar` para o Chatwoot via API para que mensagens futuras daquele contato fossem bloqueadas no funil. O usuário relata que a etiqueta não está sendo enviada.
- **Análise da Causa:** A função `deleteLeads` (localizada em `AppDataContext.tsx`) tenta fazer um `fetch` POST diretamente do navegador do usuário para a URL da API do Chatwoot (`/api/v1/accounts/.../labels`). O Chatwoot possui políticas estritas de CORS (Cross-Origin Resource Sharing) que bloqueiam requisições AJAX feitas por domínios não autorizados. Além disso, executar chamadas de API externas diretamente no front-end expõe o `api_access_token` na aba Network do navegador, sendo uma prática de risco. A requisição está sofrendo "Silent Fail" devido ao bloco try/catch no front-end.
- **Solução Ideal:** A responsabilidade de aplicar etiquetas no Chatwoot não deve ser do Front-end (React), mas do Back-end. O CRM apenas deleta o `lead` no Supabase (como já faz perfeitamente). Devemos criar um **Trigger ou Edge Function** que escute a deleção do lead, ou melhor: usar o Supabase Edge Functions para intermediar chamadas externas sem bloqueio de CORS. Como queremos velocidade, a melhor abordagem é criar uma Edge Function dedicada a gerenciar integrações com Chatwoot de forma segura, ou simplesmente fazer uma requisição para uma nova Edge Function `chatwoot-proxy` que fará a chamada de adição de etiqueta em nome do usuário sem sofrer restrições do navegador.
